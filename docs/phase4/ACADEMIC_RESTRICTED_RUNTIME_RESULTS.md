# Restricted SQL runtime identity: local support

22 November 2026, Asia/Manila. Local code and tests only.

## Changes

The academic target allowlist now accepts the additional exact name
`tgp_academic_runtime_sql`. It retains the existing exact name and legacy
demo_runtime_* fixture family for compatibility; accepting a name never waives
the privilege/membership checks. Suffix variants and arbitrary tgp_* roles are
still rejected.

A shared operator-role predicate requires tgp_academic_operator for both exact
academic runtime names. Inspection uses it before connecting; operator init
and seed also enforce it before signing or connecting. Read-only final verify
and the deployed runtime need only the verified runtime credential, not an
operator credential. HTTPS origin remains mandatory for signed/setup/runtime
actions; origin-free inspect remains read-only and cannot issue capabilities.

No runtime capability changes were necessary: SQL identity must equal the
signed target role and every connection retains TLS, privileges, signed marker,
schema/checksum and seed checks. Tests prove the new identity acquires only the
same opaque, pool-bound capability and refuses copies, borrowed providers,
actual-role/database mismatches and elevated privileges.
